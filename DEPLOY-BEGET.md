# Развёртывание на Beget — от нуля до работающего сайта

В репозитории лежат **два независимых приложения** и **один сервис**. Разворачивать
их надо по-разному, и одно из трёх на Beget вообще не поднимется. Сначала
определитесь, что именно вам нужно.

| Что | Где в репозитории | Что нужно серверу | Beget |
|---|---|---|---|
| **Репетитор — CRM** (PWA для телефона) | `src/`, собирается в `dist/` | ничего, чистая статика | да |
| **Place** (рабочие проекты, вход по логину) | `place/` | PHP 7.4+ с `pdo_sqlite` и `curl` | да |
| **Qtickets → Google Sheets** | `place/integrations/qtickets/` | Docker, постоянный процесс | **нет** |

Про Qtickets — отдельно в самом конце: на виртуальном хостинге он не работает
в принципе, и это не настройка, а ограничение тарифа.

---

## Шаг 0. Что понадобится

1. Beget, тариф «Виртуальный хостинг» (подойдёт младший).
2. В панели у сайта выбрана версия **PHP 8.x**.
3. Node.js 18+ **на вашем компьютере** — CRM собирается локально, на хостинг
   уезжает уже готовая папка. На Beget ничего собирать не нужно.

Проверить расширения PHP можно позже через самодиагностику Place (шаг 3).

---

## Шаг 1. Решите, что где лежит

Один домен — одна корневая папка `public_html`. Варианта два.

**Вариант А (рекомендую): Place в корне, CRM в подпапке.**

```
public_html/
├── index.html          ← Place
├── api.php
├── config.php
├── cron_wordstat.php
├── cron_backup.php
└── crm/                ← Репетитор — CRM
    ├── index.html
    ├── assets/
    └── ...
```

Адреса: `https://ваш-сайт/` — Place, `https://ваш-сайт/crm/` — CRM.

**Вариант Б: CRM в корне, Place в подпапке.**

```
public_html/
├── index.html          ← CRM
├── assets/
└── place/              ← Place
    ├── index.html
    ├── api.php
    └── ...
```

Адреса: `https://ваш-сайт/` — CRM, `https://ваш-сайт/place/` — Place.

Дальше в примерах используется **вариант А**. Для варианта Б поменяйте только
путь сборки на шаге 2 и папку загрузки Place.

---

## Шаг 2. Собрать CRM у себя на компьютере

Ключевой момент: **обязательно задайте `VITE_BASE`**. По умолчанию проект
собирается под GitHub Pages с префиксом `/dabudi/`, и на вашем домене все стили
и скрипты будут искаться по несуществующему адресу — получите белый экран.

```bash
npm install

# Вариант А — CRM лежит в подпапке /crm/:
VITE_BASE=/crm/ npm run build

# Вариант Б — CRM в корне домена:
VITE_BASE=/ npm run build
```

Проверьте, что подставилось правильно:

```bash
grep -o 'src="[^"]*"' dist/index.html
# должно быть /crm/assets/... или /assets/... — но не /dabudi/
```

Загружать нужно **содержимое папки `dist/`**, а не саму папку. То есть
`dist/index.html` должен оказаться как `public_html/crm/index.html`.

## Шаг 3. Развернуть Place

Подробная пошаговая инструкция со скриншотами панели — в
[`place/install-beget.md`](place/install-beget.md). Здесь только суть.

1. Загрузите в `public_html` пять файлов из папки `place/`:
   `index.html`, `api.php`, `config.sample.php`, `cron_wordstat.php`, `cron_backup.php`.

2. Скопируйте `config.sample.php` и переименуйте копию в **`config.php`**
   (шаблон оставьте на месте). Правим всегда копию: сам шаблон лежит в открытом
   репозитории, секретам там не место.

3. Откройте `config.php` и заполните два обязательных поля:

   ```php
   define('INITIAL_ADMIN_PASS', 'ваш-пароль');          // минимум 6 символов
   define('CRON_KEY', 'случайная-строка-от-20-символов'); // обязательно!
   ```

   Пока стоят заглушки, система намеренно не запустится, а задания по ссылке
   и самодиагностика закрыты. Сгенерировать ключ: `openssl rand -hex 20`.

4. Проверьте установку, подставив свой `CRON_KEY`:

   ```
   https://ваш-сайт/api.php?action=selftest&key=ВАШ_CRON_KEY
   ```

   Ждём `"итог": "ВСЁ ГОТОВО К РАБОТЕ ✓"`. Если какая-то строка `ok:false` — там
   же написано, что чинить. Без ключа страница отвечает 403: она показывает пути
   на сервере и число аккаунтов, открытой её оставлять нельзя.

5. Войдите на `https://ваш-сайт/` под логином `admin` и паролем из шага 3.
   Остальные аккаунты создаёте сами: меню профиля → «Пользователи».

### Где живёт база

Place сам создаст папку `place-data` **рядом с `public_html`**, то есть на уровень
выше — из интернета она недоступна. Это правильное поведение, ничего делать не
нужно. Если хостинг не даст туда писать, Place создаст папку внутри сайта и
закроет её через `.htaccess` — селфтест об этом честно напишет.

**Не удаляйте `place-data`** — там вся база.

## Шаг 4. HTTPS — обязательно

Панель Beget → раздел **SSL** → бесплатный сертификат Let's Encrypt.

Это не «желательно», а необходимое условие:

- **CRM не установится на телефон** без HTTPS. Service worker, офлайн-режим и
  иконка на экране «Домой» работают только на защищённом соединении.
- Place без HTTPS передаёт пароли открытым текстом.

После включения сертификата поставьте в панели редирект с `http://` на `https://`.

---

## Шаг 5. Два задания в CronTab (только для Place)

Панель → **CronTab**. Тип задания «PHP-скрипт»:

```
03:10  /home/ВАШ_ЛОГИН/ПАПКА_САЙТА/public_html/cron_wordstat.php
03:40  /home/ВАШ_ЛОГИН/ПАПКА_САЙТА/public_html/cron_backup.php
```

Точный путь виден в файловом менеджере в адресной строке.

Если удобнее «по ссылке» (тип wget/URL) — ключ обязателен:

```
https://ваш-сайт/cron_wordstat.php?key=ВАШ_CRON_KEY
https://ваш-сайт/cron_backup.php?key=ВАШ_CRON_KEY
```

Проверка: откройте ссылку бэкапа — в ответе `"ok":1`, а в `place-data/backups`
появится файл `place-ДАТА.db`. Хранятся 30 последних копий.

---

## Шаг 6. Финальная проверка

- [ ] `https://ваш-сайт/` открывает Place, вход работает
- [ ] `https://ваш-сайт/crm/` открывает CRM, видны демо-ученики
- [ ] Замок в адресной строке, `http://` редиректит на `https://`
- [ ] `api.php?action=selftest&key=...` → «ВСЁ ГОТОВО К РАБОТЕ ✓»
- [ ] На iPhone: Safari → «Поделиться» → «На экран „Домой“» ставит иконку CRM
- [ ] Ссылка cron с ключом отвечает `"ok":1`

## Подводные камни

**Белый экран у CRM.** В 9 случаях из 10 забыли `VITE_BASE` при сборке. Откройте
консоль браузера: если запросы уходят на `/dabudi/assets/...` — пересоберите с
правильным префиксом.

**CRM показывает старую версию после обновления.** Виноват service worker: он
кэширует приложение для офлайна. Пользователю нужно закрыть все вкладки сайта и
открыть заново; на iPhone — удалить иконку с экрана «Домой» и добавить снова.
Само обновление приезжает автоматически, но со следующего запуска.

**Данные CRM живут в браузере.** Это не ошибка, а устройство приложения:
ученики, занятия и оплаты хранятся в `localStorage` телефона и на сервер не
уходят. Отсюда два следствия: на другом устройстве будет пусто, и при очистке
данных браузера всё пропадёт. Резервная копия — «Настройки → Экспорт» в самом
приложении. Добавление на экран «Домой» на iOS дополнительно защищает хранилище
от автоочистки.

**Место на диске.** Place хранит базу и до 30 бэкапов. При активной работе с
картинками база растёт; следите за квотой тарифа.

**Кириллица в путях.** Не создавайте папки с русскими именами — часть утилит
Beget и PHP-функций работы с файлами на них спотыкается.

**Отдельная от GitHub Pages история.** Workflow `.github/workflows/deploy.yml`
публикует CRM на GitHub Pages и к Beget отношения не имеет. На Beget заливка
ручная (файловый менеджер или FTP), либо настраивайте деплой отдельно.

## Qtickets → Google Sheets: почему не на Beget

Сервис выгрузки — это Python-приложение на FastAPI в Docker-контейнере, которое
держит фоновые задачи и постоянно работающий процесс. Виртуальный хостинг Beget
такого не умеет: там выполняются только короткие PHP-запросы, контейнеры и
демоны не поддерживаются. Это ограничение тарифа, а не вопрос настройки.

Варианты:

1. **Google Cloud Run** — как задумано, инструкция в
   [`place/integrations/qtickets/README.md`](place/integrations/qtickets/README.md).
   Для такой нагрузки укладывается в бесплатный лимит.
2. **Любой VPS** с Docker — тот же `Dockerfile`.
3. **Не разворачивать.** Оставьте `QT_URL` и `QT_KEY` в `config.php` пустыми:
   кнопка «Qtickets» в меню помощника честно скажет, что интеграция не
   настроена, остальное приложение работает как обычно.

Когда сервис поднят, пропишите в `config.php`:

```php
define('QT_URL', 'https://qtickets-sync-xxxx.run.app');   // без /run на конце
define('QT_KEY', 'тот-же-секрет-что-RUN_KEY-в-сервисе');
```
