# Интеграции Place

## Qtickets → Google Sheets (кнопка в меню помощника)

Логика вашего Colab-ноутбука перенесена в сервис `integrations/qtickets/`
и запускается кнопкой **Qtickets** из приложения.

**Настройка по шагам — в [`integrations/qtickets/README.md`](integrations/qtickets/README.md).**
Ниже — только объяснение, почему архитектура именно такая.

---

### Почему нельзя «просто запустить Python локально»

Place — веб-приложение на хостинге, вы открываете его с любого устройства.
Браузер не может запустить Python на вашем компьютере: кнопка не сработает
с телефона, не сработает, когда компьютер выключен, а обращение со страницы
по `https://` на `http://localhost` блокируется браузером.

Поэтому логика живёт **на сервере**, а приложение только запускает её и
показывает отчёт.

### Почему через `api.php`, а не напрямую из браузера

```
Кнопка «Qtickets» в меню помощника
  └─ api.php  qtickets_run       проверяет вашу сессию, знает URL и ключ
     └─ сервис /run              сразу отдаёт job_id
        └─ фоновый поток: QTickets → расчёт → Google Sheets
  └─ api.php  qtickets_status    опрос раз в 3 секунды
     └─ прогресс, затем отчёт
```

* **Секреты не попадают в браузер.** Токен QTickets и ключ сервиса лежат в
  `config.php` и в переменных окружения — из исходников страницы их не видно.
* **Не нужен CORS**: браузер общается только со своим `api.php`.
* **Переиспользуется авторизация**: запустить выгрузку может только тот, кто
  вошёл в Place.
* **Это тот же паттерн, что и Wordstat** в v13 — новых концепций в проекте
  не появилось.

### Почему асинхронно

Скрипт читает **все** заказы QTickets — это минуты. Синхронный запрос упёрся
бы в таймаут хостинга и браузера, а кнопка «висела» бы без признаков жизни.
Поэтому запуск сразу возвращает номер задачи, а приложение опрашивает статус
и показывает прогресс («Читаю заказы… 45%»), затем — отчёт.

### Что осталось от ноутбука без изменений

Весь расчёт: `sale_day` с правилом полуночи, `parse_tab`, `city_key`,
`find_cols`, `parse_day`, окно `BACKFILL_DAYS`, пропуск сегодняшнего дня и
будущего, правило «ровно один показ на город+дату» и запись **только в пустые**
ячейки Z/AB. Заменена лишь обвязка, невозможная на сервере: авторизация Colab
→ сервисный аккаунт, `input('да')` → кнопка, `print` → отчёт в окне.

### Альтернатива без своего сервиса

Раз получатель — Google Sheets, логику можно переписать на JavaScript и
повесить прямо на таблицу (**Расширения → Apps Script**, публикация как
веб-приложение). Инфраструктуры не нужно вообще. Минус — переписывать код
с Python и URL виден в исходниках страницы, поэтому годится, только если
эндпоинт безопасен сам по себе.

## Как добавить свою кнопку в меню помощника

Всё меню — один массив `PET_MENU` в `index.html`. Новый пункт = новый объект:

```js
{run:function(tile){ /* ваш код */ }, label:'Отчёт', icon:'<path d="…"/>'}
```

Поля: `label` — подпись, `icon` — содержимое SVG 24×24, `view` — перейти
в раздел приложения, `run` — своя функция (получает плитку, чтобы показать
состояние загрузки через `tile.classList.add('busy')`), `badge:'alert'` — счётчик.
Сетка, анимации, подсветка активного раздела подхватятся автоматически.
